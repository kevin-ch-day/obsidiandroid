# Code-complete release verification checklist

This is reusable release guidance. Machine identities, local paths, dated audit
findings, run-specific metrics and operational readiness decisions belong in local
notes outside Git, loaded through gitignored `CLAUDE.local.md`.

- Record the exact source commit and package version being reviewed.
- Preserve existing run artifacts before regenerating any reusable output slot.
- Keep dataset, feature, split and implementation hashes with each evidence packet.
- Verify documented entry points and report contracts against the selected version.
- Run the required offline CI gate and record its result in the release receipt.
- Distinguish frozen paper evidence, current diagnostic output and operational
  assessment. A later code change is not a rerun of a historical experiment.
- Update release notes with shipped behavior, validation and explicit claim limits.
- Keep database migrations, account/grant changes, provider work, training and
  deployment under their separately authorized workflows.
- Verify backup artifacts and disposable restore results before making a recovery
  claim; a checksum alone does not establish successful restoration.
- Review outgoing files for credentials, operator context and unintended research
  evidence. Do not rewrite history or delete custody material during cleanup.

A completed source-code checklist does not imply production, database or recovery
readiness. Store dated decisions, exact commands and receipts locally; retain the
historical checklist in the operator archive when tracing earlier release work.
